# Публикация Malachite: что готово и что осталось сделать

Этот файл — памятка для автора проекта. Он описывает всю схему: как приложение выходит к людям,
как к вам приходят сообщения об ошибках и что нужно сделать руками.

## 1. Как к вам приходят ошибки

Плеер сам ничего не отправляет — так обещано в соглашении, и так требуют правила F-Droid.
Поэтому схема такая:

1. **Сбой.** Если пользователь разрешил (галочка при первом запуске или «Настройки → Ошибки и
   журнал»), плеер сохраняет причину сбоя у себя. При следующем запуске он показывает отчёт и три
   кнопки: «Отправить на GitHub», «Поделиться», «Удалить».
2. **Обычная ошибка** («не нашлась обложка», «исцеление сделало не то»). Пользователь включает
   журнал, повторяет ошибку и прикладывает файл `Download/Malachite-log.txt` к сообщению.
3. **Куда всё приходит.** В раздел **Issues** репозитория. Там уже есть форма «Ошибка / Bug» с
   нужными полями (версия, телефон, шаги, журнал).

Что сделать вам:

- Откройте репозиторий на GitHub → кнопка **Watch** → **All Activity**. Тогда о каждом новом
  сообщении придёт письмо на почту вашего аккаунта.
- Поставьте приложение **GitHub** на телефон и включите уведомления — сообщения будут приходить
  как в мессенджере.
- Отвечать можно прямо там. Когда ошибка исправлена, сообщение закрывается кнопкой **Close issue**.

У этой схемы есть слабое место: чтобы написать в Issues, нужен аккаунт GitHub. Для остальных
есть кнопка «Поделиться» — отчёт можно отправить любым приложением. Если вы дадите публичный
адрес (почту или Telegram для обратной связи), его можно добавить в «О приложении».

## 2. Авторство и лицензия

- Вы записаны как **главный создатель** (`Credits.kt`): имя, логотип из «Розклада», ссылка на
  Telegram-канал. Это видно в «Настройки → О приложении» и при первом запуске.
- Лицензия — **GNU GPL 3.0 или новее** с дополнительными условиями (`NOTICE.md`): код можно
  менять, но нельзя выдавать за свой; ваше имя и логотип убирать нельзя; тот, кто изменил код,
  обязан вписать себя в список «Изменили код / модифицировали».
- Без свободной лицензии приложение не примут в F-Droid. Лицензия «все права защищены», как в
  «Розкладе», туда не подходит.

Честное предупреждение: код написан ИИ. В ряде стран права на то, что целиком создано ИИ,
защищаются слабее обычного, и суд может отнестись к такой лицензии не так, как к лицензии на код,
написанный человеком. Лицензия всё равно полезна: она ясно говорит, что вы разрешаете и чего нет,
и именно её будут читать порядочные люди и площадки вроде F-Droid и GitHub.

## 3. Что нужно сделать до публикации

| Что | Зачем | Как |
|---|---|---|
| **Свой ключ подписи** | Сборки подписываются только ключом из Secrets: в репозитории ключа нет. Без него APK подписывается временным ключом и не встаёт поверх установленного плеера. | Ключ хранится только у вас и в **Settings → Secrets and variables → Actions** репозитория (секреты `SIGNING_KEYSTORE_BASE64`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`). Как только секреты добавлены, сборки на GitHub подписываются им сами. Сборка падает, если в репозитории окажется файл ключа, закрытый ключ, пароль или токен (`tools/check_no_secrets.py`). В F-Droid свой ключ не нужен: он подписывает сам. |
| **Имя репозитория** | `stromik839/malachite`. | Если переименуете (Settings → General → Repository name), поменяйте `SOURCE_URL` в `Credits.kt` и адреса в `docs/fdroid-metadata.yml`. |
| **Скриншоты** | F-Droid показывает их на странице приложения. | Снимаются на эмуляторе с демо-библиотекой (без чужих песен и обложек) и кладутся в `fastlane/metadata/android/*/images/phoneScreenshots/`. |
| **Метка версии** | F-Droid собирает приложение по меткам. | На GitHub: Releases → Draft a new release → тег `v0.2.0` на проверенном коммите. |

## 4. Как попасть в F-Droid

### Что F-Droid проверяет — и что уже соблюдено

| Требование | Состояние |
|---|---|
| Свободная лицензия | ✔ GPL-3.0-or-later; дополнительные условия из `NOTICE.md` — из числа тех, что GPL прямо разрешает (раздел 7) |
| Нет рекламы, аналитики, трекеров, закрытых библиотек (Google Play Services, Firebase…) | ✔ библиотеки только из Google Maven и Maven Central, все свободные |
| Сборка из исходников одной командой, без готовых двоичных файлов | ✔ `gradle assembleRelease`; подпись в сборке необязательна — F-Droid подписывает своим ключом |
| Описание, значок, список изменений в репозитории | ✔ `fastlane/metadata/android/` (нет только скриншотов) |
| Сеть только по действию пользователя, ничего не отправляется само | ✔ |
| Версия по метке (тегу) | ✘ нужен тег `v0.2.0` |

### Порядок действий

1. Довести версию до состояния «можно показывать людям»: проверить на телефоне, снять скриншоты.
2. Переименовать репозиторий (если хочется) — **до** заявки: в F-Droid записывается его адрес.
3. Поставить тег `v0.2.0`.
4. Завести аккаунт на https://gitlab.com (F-Droid живёт там) и выбрать один из двух путей:
   - **Простой:** открыть https://gitlab.com/fdroid/rfp/-/issues и создать заявку «Request For
     Packaging» — ссылка на репозиторий, лицензия, краткое описание. Дальше приложение
     упаковывают волонтёры; очередь большая, срок — от пары недель до нескольких месяцев.
   - **Быстрый:** самому предложить файл описания в https://gitlab.com/fdroid/fdroiddata
     (fork → файл `metadata/app.malachite.player.yml` → merge request). Заготовка файла лежит в
     `docs/fdroid-metadata.yml`, останется вписать адрес репозитория и метку; заголовок заявки —
     «New app: Malachite». F-Droid сам называет этот путь самым быстрым
     (https://f-droid.org/docs/Submitting_to_F-Droid_Quick_Start_Guide/). Файл Claude подготовит
     целиком, отправить его нужно со своего аккаунта.
5. Ответить на вопросы проверяющих (они пишут в той же заявке). После одобрения приложение
   появляется в каталоге в течение нескольких дней.
6. Дальше обновления выходят сами: новая версия в `app/build.gradle.kts` + новый тег — F-Droid
   замечает метку и собирает её.

### Что стоит знать заранее

- **Пометки (anti-features).** Приложение получит **NonFreeNet** («зависит от несвободных сетевых
  сервисов»): поиск текстов и обложек идёт через iTunes, Deezer, Genius и другие. Это не запрет,
  а честная пометка на странице.
- **Подпись.** F-Droid подписывает сборки **своим** ключом. Поэтому приложение из F-Droid не
  ставится поверх APK с GitHub и наоборот — человек выбирает один источник. Данные при этом лежат
  в главной папке и переживают переустановку.
- **Код написан ИИ.** Запрета на это в правилах F-Droid нет, но проверяющие могут спросить о
  лицензии и происхождении кода. Отвечать честно: так и написано в самом приложении.
- **Онлайн-раздел.** Источники — открытые каталоги и официальные 30-секундные отрывки; он
  выключен по умолчанию. Если проверяющие попросят, раздел можно убрать из сборки для F-Droid.
- **IzzyOnDroid не подходит.** Это второй большой каталог, но в его правилах прямо сказано:
  приложения, код которых целиком или частично написан генеративным ИИ, отклоняются
  («Vibe-coded apps will be rejected»; https://izzyondroid.org/docs/general/AppInclusionPolicy/).
  Скрывать происхождение кода нельзя и бессмысленно — оно указано в самом приложении, а за
  сокрытие исключают. Заявку туда не подаём.
- **Если F-Droid откажет.** Остаются свои релизы на GitHub: приложение **Obtainium** ставит и
  обновляет программы прямо из GitHub Releases по адресу репозитория. Для этого нужны только свой
  ключ подписи (секреты из раздела 3) и релиз с меткой, к которому приложен APK.

Готовый текст заявки и пошаговая инструкция для GitLab — в `docs/fdroid-request.md`.

## 5. Пожертвования

Сделано через криптовалютные адреса (без банковских данных): Bitcoin, TRX, GRAM (TON) и USDT в
четырёх сетях. Они записаны в `Credits.kt` (`DONATE_WALLETS`), показаны в «Настройки → О
приложении → Поддержать автора» и в `README.md`. Каждый адрес проверен по контрольной сумме.
F-Droid показывает на странице приложения только Bitcoin (и Litecoin) — адрес Bitcoin уже вписан
в `docs/fdroid-metadata.yml`.

Если позже появится страница для пожертвований (Liberapay, Ko-fi и подобные), её адрес
вписывается в `DONATE_URL` в `Credits.kt` и в поле `Donate` файла F-Droid.

## 6. Языки интерфейса

- Тексты интерфейса написаны в коде по-русски и проходят через `tr("…")`. Английские
  переводы лежат в `core/src/main/resources/i18n/en.txt`: две строки на запись (русский текст,
  английский), пустая строка между записями; `{}` — место для значения.
- Язык выбирается сам: русский, если язык телефона русский, для всех остальных — английский.
  Изменить можно на первом экране и в «Оформление → Язык интерфейса» (Авто / Русский / English).
- Добавили или изменили русский текст → добавьте перевод в `en.txt`. Сборка на GitHub
  остановится, если у какого-то текста перевода нет (`python3 tools/i18n.py check`;
  `python3 tools/i18n.py missing` покажет, чего не хватает; `python3 tools/i18n.py wrap`
  обернёт новые тексты в `tr(…)`).
- Ещё один язык — это ещё один такой файл и строчка в `Language.kt`.

## 7. Обновления

- Изменился текст соглашения по существу → увеличьте `Terms.VERSION` в `Legal.kt`: приложение
  покажет соглашение всем заново.
- Новая версия → увеличьте `versionCode` и `versionName` в `app/build.gradle.kts` и добавьте файл
  `fastlane/metadata/android/ru-RU/changelogs/<versionCode>.txt` со списком изменений.
